# Stodola Equation Verification Study

This repository contains the automation and analysis pipeline used for the labyrinth-seal fin-count scaling study.

The workflow automates the generation and submission of the CFD cases, extraction and verification of the resulting mass-flow data, and the subsequent analysis of the fin-count scaling relation.

## Pipeline Overview

The complete workflow is executed in the following order:

```text
 Run simulations
        ↓
 CFD post-processing (validation/ workflow)
        ↓
 Extract and verify simulation results
        ↓
 Analyze results and generate plots
```

> [!IMPORTANT]
> **CFD post-processing is not performed by these scripts.**
> The required CFD quantities are generated by the post-processing workflow in the [`validation/`](../../../tree/main/valdiation-pipeline) folder of this repository. The automation pipeline described here operates on the resulting simulation and post-processing data.

In other words:

- the **simulation script** creates and submits the CFD cases;
- the **post-processing workflow in [`validation/`](../../../tree/main/valdiation-pipeline)** processes the completed CFD solutions;
- the **extraction/verification script** collects the relevant quantities from the resulting files;
- the **analysis script** uses the extracted YAML data to perform the scaling-law analysis and generate the final figures.

---

## Stage 1: Simulation Submission

The first stage of the workflow is the automated generation and submission of the CFD cases.

The simulation script defines the required study configurations, generates the corresponding simulation cases, and submits them to the TRACE simulation environment. Its purpose is to automate the **case setup and execution**, not to analyze results.

The output of this stage is a set of completed TRACE simulations containing the flow solutions and the associated post-processing data.

Run this script first. The subsequent stages should only be executed once the required simulations have completed.

---

## Stage 2: Result Extraction and Verification

The second stage operates on the completed simulations.

The script reads the generated TRACE post-processing files from the simulation directories and extracts the relevant **mass-flow rates**. For each simulation, the script:

1. Locates the corresponding completed simulation directory.
2. Reads the `d0_primitives_*.dat` files produced by the TRACE post-processing.
3. Identifies the inlet and outlet zones.
4. Extracts the outlet `MassFlow`.
5. Handles the different averaging types: `flux`, `mass`, and `area`.
6. Organizes the available results according to simulation configuration, inlet-swirl condition, fin count, and averaging method.
7. Compares mass-flow ratios between different fin counts.
8. Checks the results against the theoretical fin-count scaling relation.
9. Writes a text report containing the calculated ratios, predicted ratios, differences, and percentage errors.

The script tolerates incomplete simulation sets: unavailable or missing simulations are skipped rather than causing the entire analysis to fail.

### Scaling relation

The verification is based on the relation

```math
\frac{\dot{m}(z_2)}{\dot{m}(z_1)} = \sqrt{\frac{z_1}{z_2}}
```

or equivalently,

```math
\dot{m}(z)\,\sqrt{z} = \text{constant}
```

The script compares the CFD-derived mass-flow ratio against this theoretical prediction. For each available pair of fin counts $z_1 < z_2$, it calculates:

- CFD mass flow at $z_1$;
- CFD mass flow at $z_2$;
- actual mass-flow ratio;
- predicted mass-flow ratio;
- ratio difference;
- percentage error.

The output is written to a text file for direct inspection of the scaling-law agreement.

## Stage 3: Scaling Analysis and Visualization

The third stage performs the main analysis and generates the figures used to assess the scaling relation.

This script does **not** read the raw CFD solutions directly. Instead, it reads the already processed `values_*.yml` result files generated by the preceding post-processing workflow.

For each result file, the script extracts the stored `MassFlow` value from the selected averaging block. The default averaging type is `mass`; `flux` and `area` are also available.

The YAML files are organized by configuration and fin count, with separate files for the non-swirl and swirl cases. For example:

```text
values_FC_F3.yml     # convergent, F3, no swirl
values_sFC_F3.yml    # convergent, F3, prescribed swirl (note the "s" prefix)
```

### Studied configurations

| Case  | Configuration                      |
| ----- | ---------------------------------- |
| `FS`  | Smooth configuration               |
| `FC`  | Convergent configuration           |
| `FCH` | Convergent half-step configuration |
| `FD`  | Divergent configuration            |
| `FDH` | Divergent half-step configuration  |

Each configuration is analyzed both without inlet swirl and with prescribed inlet swirl.

The analysis uses fin counts starting from **F2**. F1 is intentionally excluded because the first fin has no upstream step and therefore does not behave like the subsequent fins under the scaling relation.

### Equation 2.3 analysis

For every configuration and swirl condition, the script loads all available fin-count results and compares the CFD mass-flow values against

```math
\dot{m}(z_2) = \dot{m}(z_1)\,\sqrt{\frac{z_1}{z_2}}
```

All available fin-count pairs are considered. Consecutive pairs are handled first (`F2–F3`, `F3–F4`, `F4–F5`, ...), followed by the remaining combinations. For each pair, the script calculates the predicted mass flow and compares it with the CFD value.

The percentage error is

```math
\text{error} = \frac{\dot{m}_{\text{predicted}} - \dot{m}_{\text{CFD}}}{\dot{m}_{\text{CFD}}} \times 100
```

The script then calculates summary statistics:

- mean absolute percentage error;
- maximum absolute percentage error;
- standard deviation of the percentage error.

---

## Generated Outputs

The analysis script produces three types of graphical output.

### 1. Error heat maps

One combined heat map is generated for each seal configuration, combining both inlet conditions in a single matrix:

- the **upper-right triangle** contains the percentage errors for the non-swirl cases;
- the **lower-left triangle** contains the percentage errors for the swirl cases;
- the diagonal is left empty, since comparing a fin count with itself is meaningless.

This allows the effect of inlet swirl on the scaling-law accuracy to be compared directly for the same seal configuration. Five heat maps are produced in total, one per configuration.

### 2. Mass-flow trend plots

A trend plot is generated for each configuration showing:

- CFD mass flow without swirl;
- CFD mass flow with swirl;
- the corresponding theoretical $1/\sqrt{z}$ scaling curves.

The theoretical curve is anchored at the smallest available fin count for each variant, giving a direct visual comparison between the CFD results and the expected scaling behaviour.

### 3. Summary comparison

A combined bar chart summarizes the **mean absolute percentage error** for all five configurations, shown separately for the no-swirl and swirl cases. This gives an overall view of how well the scaling relation represents the CFD results across seal geometries and inlet conditions.

### Output structure

```text
eq23_results/
├── eq23_report_<case>.txt
├── eq23_heatmap_<case>.pdf
├── eq23_trend_<case>.pdf
└── eq23_summary_comparison.pdf
```

The text reports contain the individual mass-flow values, pairwise comparisons, predicted values, absolute differences, percentage errors, and summary statistics. The PDF files contain the graphical analysis described above.

## Interpretation Note

The fin-count scaling relation should be interpreted as a **scaling approximation**, not as a complete physical model of labyrinth-seal leakage.

The purpose of this analysis is to quantify **how well the scaling relation represents the CFD results for the studied geometries and flow conditions**. It should not be interpreted as a standalone validation of the equation for general labyrinth-seal design.

## Usage

| Stage | Purpose                                         | Main input                            | Main output                                       |
| ----- | ----------------------------------------------- | ------------------------------------- | ------------------------------------------------- |
| **1** | Generate and submit CFD cases                   | Study parameters                      | TRACE simulations                                 |
| **2** | Extract and verify simulation data              | Completed TRACE/post-processing files | Mass-flow verification report / processed values  |
| **3** | Analyze scaling behaviour and visualize results | `values_*.yml` files                  | Reports, heat maps, trend plots, summary plot     |

Stage 3 does **not** retrieve CFD results from the simulations itself; it works on the processed YAML data. The CFD post-processing is handled separately by the [`validation/`](../../../tree/main/valdiation-pipeline) workflow.

### Step 1: Run the simulation pipeline

Run the **Stage 1** script to generate and submit the TRACE simulations, then wait for the cases to finish.

### Step 2: Post-process, extract, and verify

Run the post-processing workflow in [`validation/`](../../../tree/main/valdiation-pipeline), then run the **Stage 2** script to read the completed files and check the relevant mass-flow quantities.

### Step 3: Generate the analysis

```bash
python laby_eq23_check.py
```

The script reads the `values_*.yml` files and writes the reports and figures to the configured output directory.

## Configuration

The main paths, studied configurations, fin-count range, averaging method, and plot settings are defined in the configuration section of the analysis script:

```python
VALUES_DIR = Path("./data/fins")
OUT_DIR = VALUES_DIR / "eq23_results"

DEFAULT_AVG = "mass"   # one of: "flux", "mass", "area"

MIN_FIN = 2
MAX_FIN = 9
```

These settings can be changed directly when applying the workflow to a different dataset.

## Summary

This pipeline automates the study of labyrinth-seal mass-flow scaling with fin count. The computational stages (CFD simulation, CFD post-processing, numerical verification, and final visualization) are kept distinct.

The central analysis evaluates the approximation

```math
\dot{m}(z_2) = \dot{m}(z_1)\,\sqrt{\frac{z_1}{z_2}}
```

against CFD results for five seal configurations, with and without prescribed inlet swirl. The resulting reports and figures quantify the accuracy of this scaling relation across fin count, seal geometry, and inlet-swirl condition.
